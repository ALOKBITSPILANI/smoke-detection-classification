# Smoke Detection Classification

## a. Problem statement

Build and compare five supervised classification models that predict whether an IoT sensor reading indicates a fire alarm. The models are evaluated on a held-out test split and can also be evaluated on another labeled CSV through the Streamlit application.

## b. Dataset description

The project uses `smoke_detection_iot.csv`, containing 62,630 sensor readings and the binary `Fire Alarm` target. The first two columns (`Unnamed: 0` and `UTC`) are excluded. The remaining 13 numeric sensor/count fields are the model features. There are no missing values; the target contains 44,757 positive and 17,873 negative examples.

Dataset source: [Smoke Detection Dataset on Kaggle](https://www.kaggle.com/datasets/deepcontractor/smoke-detection-dataset).

## d. Models used

All models use the same stratified 80/20 train-test split (`random_state=42`). Scaling is included in the Logistic Regression, K-Nearest Neighbors, Gaussian Naive Bayes, and linear SVM pipelines. Decision Tree is used without scaling. `test_data.csv` is the held-out labeled test set. Metrics are generated by running `python train_models.py`.

### Model observations

| ML Model Name | Observation about model performance |
| --- | --- |
| Logistic Regression | Strong overall performance with 0.9893 accuracy and 0.9925 F1, but below the tree and KNN models on this split. |
| Decision Tree | Near-perfect scores and 1.0000 recall; it missed no fire-alarm examples in the test set. |
| K-Nearest Neighbors | Near-perfect performance and the highest AUC (0.9999); it made one false negative and one false positive. |
| Gaussian Naive Bayes | Highest recall after the tree/KNN range, but many false alarms reduce accuracy to 0.7979 and MCC to 0.4594. |
| Support Vector Machine | Strong and balanced results (0.9926 accuracy, 0.9948 F1), though below the top two models. |
| Overall winner | Decision Tree, narrowly, because it combines near-perfect scores with no missed fire alarms on this test split. KNN has the highest AUC and is effectively tied overall. |

**Evaluation limitation:** The split is stratified and shuffled as a standard classification benchmark, but these sensor readings are time-ordered. `CNT` is retained as a feature because only the first two columns were excluded, and it correlates with the target in this dataset. Neighboring readings can be highly similar, so these results may be optimistic for predicting a later, unseen time period. They should not be interpreted as a temporal deployment guarantee.

### Streamlit app

The app loads the saved models and evaluates a labeled CSV without retraining. It includes a bundled holdout split, CSV upload, multi-model metrics comparison, a confusion matrix, and a classification report.

## Run locally

```bash
python -m pip install -r requirements.txt
python train_models.py
streamlit run app.py
```

The training script writes five fitted pipelines under `model/`, creates `test_data.csv`, and saves scores and metadata to `metrics.json`.
